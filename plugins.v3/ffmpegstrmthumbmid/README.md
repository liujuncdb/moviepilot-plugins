# FFmpegStrm缩略图·中间帧魔改

MoviePilot V3 插件。针对 `.strm` 媒体库生成与 strm 同名的 `-thumb.jpg` 缩略图。

## 与常见做法的区别

传统做法把截取时间写死（例如固定第 30 秒）。当影片短于该时间点时 ffmpeg 直接报错，短片永远得不到缩略图。

本插件先用 `ffprobe` 探测时长，再截取 `时长 / 2 + 偏移` 处的一帧：

- 短片（哪怕只有几秒）也能正常出图
- 探测不到时长时回退固定时间点，若该时间点超过时长则自动改取中点
- 时间统一钳制在 `[0.3s, 时长-0.1s]`，避免越界
- 中点截图失败时才回退首帧；若链接本身不可读（moov 缺失/数据无效）直接跳过，不再白等超时

## 配置项

| 配置 | 说明 |
| --- | --- |
| 启用插件 | 总开关 |
| 立即运行一次 | 保存后立即在后台跑一次 |
| 重启后自动续跑 | 插件加载（含 MoviePilot 重启、容器重建）后自动继续补缺失图 |
| 覆盖生成 | 关闭时只补缺失（推荐），开启则重做所有已存在的图 |
| 自动截取中间帧 | 关闭则使用下方固定时间点 |
| 中间帧偏移 | 相对中点偏移的秒数，负数向前 |
| 扫描路径 / 排除路径 | 每行一个容器内路径 |
| 生成策略 | `数量=暂停秒数`，例如 `100=60`，每处理 N 个暂停一次 |
| 定时 Cron | 默认 `0 2 * * *` 每天凌晨补一次 |

## 稳定性设计

- **仅补缺失**：已存在的 `-thumb.jpg` 直接跳过，重跑代价极小
- **断点续跑**：中途被重启打断不丢图，下次自动跳过已生成的
- **扫描互斥**：插件重载后新旧扫描不会并发重复处理（内核 flock，进程退出自动释放）
- **不被打断**：检测到扫描进行中时，保存配置只取消定时任务，不打断当前扫描
- **进度可见**：每 50 个文件输出一行进度、耗时与预计剩余时间

## 已知限制

若媒体源本身不可读（例如 115 网盘上内容为全零的空壳文件，`curl` 返回 206 但数据全是 `0x00`），ffmpeg 会报 `moov atom not found` / `Invalid data found`，这类文件无法生成缩略图，需要重新下载源文件。
