# FFmpegStrm缩略图·中间帧魔改

MoviePilot V3 插件。为 `.strm` 媒体库生成与 strm 同名的 `-thumb.jpg` 缩略图。

## 鸣谢

本插件基于 **imaliang** 的 MoviePilot 插件 **FFmpegStrmThumb** 二次开发，原版仓库：

- https://github.com/imaliang/moviepilot-plugins

原版把「为 STRM 媒体库批量生成缩略图」这件事跑通了，本版只是在其基础上改了截取策略、补了工程健壮性。感谢原作者。

## 与原版的主要改进

原版核心逻辑是 `ffmpeg -ss {时间点} -i "{strm}" -vframes 1`，时间点默认写死 `00:03:01`，不探测片长。

| 能力 | 原版 FFmpegStrmThumb | 本版（中间帧魔改） |
| --- | --- | --- |
| 截取时间 | 固定 `-ss` 时间点（默认 00:03:01） | 先 `ffprobe` 探测片长，再按比例截取，默认正中间 |
| 短视频 | 片长短于固定时间点时 ffmpeg 报错，出不了图 | 自动落在片内，并钳制在 `[0.3s, 片长-0.1s]`，几秒的片子也能出图 |
| 截取位置 | 只能改固定时间字符串 | 「截取位置(%)」5%~95% + 「中间帧偏移(秒)」两个可调项 |
| 只补缺失 | 已存在 `-thumb.jpg` 时跳过 | 同样跳过，且在扫描阶段先统计待处理数量，日志可见 |
| 中断恢复 | 插件重启后从头重扫 | 逐文件独立判断，天然断点续跑；插件加载 15 秒后自动补缺（可关） |
| 扫描互斥 | 无 | 内核 `flock` 加锁，重载后新旧扫描不并发，进程退出自动释放 |
| 插件重载 | 扫描会被打断 | 检测到扫描进行中时不打断，只取消定时任务 |
| 失败处理 | 统一 error 日志 | 区分 `ok/skip/fail`；`moov atom not found`、`Invalid data` 直接跳过，不再白等超时 |
| 超时控制 | 无超时，坏链会长时间挂住 | `ffprobe` 8s、`ffmpeg` 18s，超时即放弃该文件 |
| 日志 | 逐条 info/error | 每 50 个文件输出进度、耗时、预计剩余；结束汇总成功/跳过/失败 |
| 生成策略 | 每 N 个暂停 M 秒 | 保留该能力，并对非法格式容错，不会因写错配置导致插件加载失败 |

实测吞吐：同一批媒体库下，本版约 19 个/分钟，原版固定时间点在短视频上大量报错重试，速度被拖慢。

## 配置项

| 配置 | 说明 |
| --- | --- |
| 启用插件 | 总开关 |
| 立即运行一次 | 保存后立即在后台跑一次 |
| 重启后自动续跑 | 插件加载（含 MoviePilot 重启、容器重建）后自动继续补缺失图 |
| 覆盖生成 | 关闭时只补缺失（推荐），开启则重做所有已存在的图 |
| 自动截取中间帧 | 关闭则使用下方固定时间点 |
| 截取位置(%) | 默认 50（正中间），范围 5~95 |
| 中间帧偏移 | 相对截取点的秒数，负数向前 |
| 扫描路径 / 排除路径 | 每行一个容器内路径 |
| 生成策略 | `数量=暂停秒数`，例如 `100=60` |
| 定时 Cron | 默认 `0 2 * * *` 每天凌晨补一次 |

## 已知限制

若媒体源本身不可读（例如网盘上内容为全零的空壳文件，`curl` 返回 206 但数据全是 `0x00`），ffmpeg 会报 `moov atom not found` / `Invalid data`。这类文件任何工具都截不了帧，需要重新下载源文件。
